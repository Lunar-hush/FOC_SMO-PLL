FOC无感闭环调试问题总结

问题背景

移植SguanFOC库到STM32G4平台后，电机无法切入无感闭环，表现为：

  1. PLL切入后电机高频抖动不转动
  2. 使用atan2估算的角度与开环拖动角度对不上
  3. 闭环后转速不跟随电位计给定变化

根本原因分析

经过对比源程序和移植程序，发现5个关键问题：

问题1：SMO滑模观测器符号函数错误

滑模观测器核心算法使用了错误的函数，导致反电动势估算完全错误。

修改前（错误代码）

// Foc.c 第313-316行
error = run->Output_Ix - run->Input_Ix;
Value_Limit(&error, 1.0f, -1.0f);  // ❌ 限幅函数，保留原始误差幅值
Ex = error * smo->h;

修改后（正确代码）

// Foc.c 第313-315行
error = run->Output_Ix - run->Input_Ix;
error = Value_Sign(error);   // ✅ 符号函数，返回±1等幅开关信号
Ex = error * smo->h;

原理说明

  • Value_Sign：返回+1或-1，产生等幅开关信号，是滑模观测器的核心
  • Value_Limit：限幅到[-1,1]，但保留了误差的原始幅值信息
  • 影响：反电动势Output_Ex不再是开关信号，atan2计算的角度完全错误

问题2：PLL鉴相角度多乘极对数

PLL的OutRe已经是电角度，但代码中又乘了一次极对数，导致鉴相错误。

修改前（错误代码）

// Foc.c 第474行
fast_sin_cos(pll->go.OutRe * motor.Poles, &Sine, &Cosine);  // ❌ 多乘了Poles

修改后（正确代码）

// Foc.c 第473-474行
/* ★ OutRe已经是电角度，不要再乘Poles！*/
fast_sin_cos(pll->go.OutRe, &Sine, &Cosine);  // ✅ 直接使用电角度

原理说明

  • PLL.go.OutRe：定义为电角度（rad），已包含极对数
  • 错误后果：电角度×极对数 = 角度×49（Poles=7），PLL无法锁定

问题3：高速域速度单位错误

value.High_Wm应该存储机械角速度，但代码中存的是电角速度。

修改前（错误代码）

// Foc.c 第724行
value.High_Wm = PLL_encoder.go.OutWe;  // ❌ 电角速度（rad/s）

修改后（正确代码）

// Foc.c 第724行
value.High_Wm = PLL_encoder.go.OutWe / (float)motor.Poles;  // ✅ 机械角速度

原理说明

  • 转换公式：机械角速度 = 电角速度 / 极对数
  • High_Wm应与Low_Wm单位一致，都是机械角速度

问题4：角度融合逻辑错误

将机械角度和电角度直接加权融合，单位混乱导致角度跳变。

修改前（错误代码）

// Foc.c 第759-760行
encoder.Real_Pos = Value_normalize(value.Low_angle  * Normalized_Gain
                                 + value.High_angle * value.Sensorless_Gain);  // ❌ 混合单位

修改后（正确代码）

// Foc.c 第740-772行（简化版）
if (Speed_Abs <= value.Sensorless_AbsMin)
{
    /* 低速域：用开环机械角速度积分 */
    Re = Value_normalize(value.Low_angle * (float)motor.Poles);  // ✅ 机械角→电角
}
else
{
    /* 高速域：用观测器角度 */
    Re = value.High_angle;  // ✅ 已经是电角度
}

encoder.Real_Re = Re;  // ✅ 直接用电角度，不做加权融合

原理说明

  • value.Low_angle：机械角度（rad）
  • value.High_angle：电角度（rad）
  • 正确：低速用开环电角度，高速用观测器电角度，直接切换

问题5：速度环被注释导致转速不跟随

切入闭环后，转速不跟随电位计给定变化。

修改前（错误代码）

// Foc.c 第807-810行
//    Transfer_PID_Loop(&Velocity, foc.Target_Speed, encoder.Real_Speed);  // ❌ 被注释
//    foc.Target_Iq = Velocity.run.Output;                                  // ❌ 被注释

foc.Target_Iq = SL_OPEN_IQ;  // ❌ 固定2.0A，不随速度环调节

修改后（正确代码）

// Foc.c 第807-810行
Transfer_PID_Loop(&Velocity, foc.Target_Speed, encoder.Real_Speed);  // ✅ 启用速度环
foc.Target_Iq = Velocity.run.Output;                                  // ✅ PID输出调节Iq

关键经验总结

1. 滑模观测器核心

  • 必须使用符号函数：sign(error)产生±1开关信号
  • 不能用限幅函数：limit会保留误差幅值，破坏滑模特性
  • 反电动势估算：atan2(-Eα, Eβ)需要准确的开关信号

2. PLL电角度理解

  • OutRe定义：电角度（rad），已包含极对数
  • OutWe定义：电角速度（rad/s），已包含极对数
  • 转换规则：
    • 电角度 → 机械角度：除以Poles
    • 电角速度 → 机械角速度：除以Poles
    • 机械角度 → 电角度：乘以Poles

3. 角度融合策略

  • 不要混合单位：机械角度和电角度不能直接加权
  • IF模式：低速用开环，高速用观测器，直接切换
  • 切换点对齐：第一次进入高速域时，预置电流环积分项

后续优化建议

1. 切换回PLL角度模式

当确认SMO工作正常后，可以将atan2模式切换为PLL模式：

#if 0   /* 修改为0，使用PLL角度 */
    float fThetaE = atan2f(-SMO.alpha.Output_Ex, SMO.beta.Output_Ex);
    value.High_angle = Value_normalize(fThetaE);
#else
    value.High_angle = PLL_encoder.go.OutRe;   /* 使用PLL滤波角度 */
#endif

优势：

  • PLL滤波后角度更平滑
  • 减少反电动势谐波对角度的影响
  • 高速运行更稳定

2. 低速保护

当前状态机不会从IDLE切回OPEN，低速时可能存在角度不准问题。建议：

  • 添加低速检测逻辑
  • 或者使用高频注入（HFI）提高低速性能

3. 参数调优

根据实际电机参数调整：

  • SMO的h参数（滑模增益）
  • PLL的Kp、Ki参数
  • 速度环的Kp、Ki参数
  • 切入闭环的阈值（Sensorless_AbsMax）
